# 会话内串行批量提取，持久草稿与审核快照保护

2026-09-21。实现基线 main bc32dc35，实施分支 codex/tracking-batch-review；accepted 表示本次已采纳的选择，不代表已合并或发布。

## 背景与决定

用户需要按日期选笔记、批量提取并逐篇确认，核心是避免重复推理及误覆盖正式信息。沿用 [ADR-0001](0001-tracking-ledger-and-reviewed-extractions.md) 的正式账本和审核草稿边界。

- 批次保存在现有 actionProcessingStore，串行 await 单篇结果；不增加任务表和恢复调度器。关闭弹窗/切页继续，退出应用后重新选择范围，复用 tracking_extractions 中有效结果。
- 模型请求前由主进程读取笔记、操作、完整模板，生成带 v3 前缀的输入指纹。模型与保存使用同一快照；执行中修改不把旧模型结果伪装成当前结果。
- 两个审核入口共用 TrackingReview。确认事务对比审核时正式事项及本笔记进展的摘要，替换需要明确同意；同分类规范名称完全相同不能继续新建，需用户选择关联。
- 保留已有稳定 ID 与人工状态保护，不把本轮绑定为完整删除、恢复、合并或模板编辑项目。

## 备选与后果

没有采用持久任务队列：用户接受退出后重新选范围，草稿已落库，恢复队列的复杂度目前没有必要。

没有仅保留 MAX(template.version)：它不能检测其他模板内容变化。完整模板指纹是保守失效策略，模板任意变化会令既有草稿过期；旧 confirmed 仍可读，旧 pending 要重新提取。

没有增加所有记录的 revision 列：既有事务加原值摘要足够。当前摘要包括全部事项，可能因无关事项变动要求重载；账本变大时再缩小受影响目标集合。Renderer 同笔记锁不承诺跨独立窗口互斥，正式写入仍受数据库检查保护。

不做语义自动合并；相似候选交由用户判断。已确认旧进展仍沿用按笔记物理替换，明确同意不是恢复能力，恢复与合并仍属于 [ADR-0002](0002-tracking-recoverable-changes.md) 的未完成范围。

实现、接口和验证依据：[事项架构 §11](../architecture/tracking.md#11-批量提取实施记录与验证b01b06)。
