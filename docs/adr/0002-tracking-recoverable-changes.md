# 保留可恢复的事项变更，以稳定 ID 承接合并历史

全局事项中心增加人工编辑、删除、合并和模板配置后，当前“审核时物理删除本笔记旧更新”的方式会丢掉用户修正，也无法支撑回收站。拟采用软删除、旧更新替代标记、合并来源到目标的稳定 ID 重定向，并增加一张简单操作记录表，与业务写入同事务保存关键前后值。

状态为 proposed：这是完整设计及安全默认值。TC1 已在未提交工作树引入人工状态保护和事项操作记录，软删除/合并/替代保留尚未实现；不得据此宣称整项决策落地。详情以[事项架构 §10](../architecture/tracking.md#10-全局事项管理中心)及其 §10.8 实施记录为准；任务见[实施清单](../superpowers/plans/2026-09-20-tracking-center.md)。

## 取舍

- 不采用硬删除再靠提取 JSON 恢复：JSON 不完整反映人工修正，旧 ID 也不能安全重建。
- 不采用事件溯源或全量版本库：正式事项/更新表继续是真源，操作表仅做简单追溯；不提供通用回放、自动撤销或合并拆分。
- 不给全部表加修订号、统一请求 ID：普通编辑复用事务内原值快照检查，模板复用 version，审核与合并比较影响集合及持久状态。重复删除/恢复幂等，重复合并必须检查目标一致。
- 关系仍保存在更新中；合并产生的自关联退出有效集合并留痕，不新增图关系表。
- 模板使用稳定 ID，配置变化不抹去旧属性/状态；字段改名不自动迁移旧键。默认模板种子也必须适配，避免改名后重复生成。

## 后果

所有读取入口（笔记、中心、聊天、候选、MCP）必须一致处理删除/替代标记和合并 ID，不能只修改新页面。历史提取保留旧名称与证据，读写边界解析规范 ID；后续重提取必须预览人工修改/删除受到的替换影响。

历史与操作记录会增加本地存储，本版不自动清理。旧版本不认识新可见性规则，降级需配套备份，不能承诺直接打开新库安全。此前已物理删除的更新无法补回。

本决策扩展而非推翻 [ADR-0001](0001-tracking-ledger-and-reviewed-extractions.md)：继续本地账本、稳定身份、先审核、按笔记替换当前进展及只读外部 MCP。实施时更新主文档的实际行为与本 ADR 状态，不覆盖 ADR-0001 的历史基线。
