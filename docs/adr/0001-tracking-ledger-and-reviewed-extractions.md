# 用本地事项账本承接长期记忆，提取结果先审核再生效

用户需要跨周记住商机、交付和产品工作，同时要求少表、少界面、优先验证提取准确率。因此保留原始笔记为事实材料，在现有 SQLite 中保存事项、事项更新和提取记录；模型产生草稿，用户确认后才修改正式数据。事项以 ID 延续身份，名称只是描述；重新提取只替换本笔记的正式更新，不清除其他笔记的进展。

这是对本会话已作决策的追记，不是 2026-09-20 新批准一套架构。落地基线：`174b0d9a`（账本、身份与审核流程）、`68aa953d`（聊天读写）。详细证据与偏差见 [事项架构](../architecture/tracking.md)。

## 取舍与后果

- 没有引入外部记忆服务或通用知识图谱。早期调研中的派生图索引是候选方向，不是当前依赖；当前优先复用 SQLite、操作机制和笔记页。
- 不增加独立关系表：关联作为有证据的事项更新保存。代价是关系依赖进展记录，重提取替换记录也会影响关系；它不是独立维护的关系图。
- 提取记录落库，避免重复推理，并保留被替代的提取历史。但确认会重写该记录的 JSON，旧数据改名也会回填 ID，不能把它称作不可变事件日志。
- 周报留给 Codex 等调用方组织，SuperTing 通过只读 MCP 提供事项上下文。时间过滤、模板配置和商机生命周期尚有缺口，不由此 ADR 宣称完成。
